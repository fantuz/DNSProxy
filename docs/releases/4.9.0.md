## DNSProxy Modern 4.9.0

This release improves the optional Linux desktop monitor's activity chart and
information layout, and reduces repeated build setup and test time in CI.

### Faster sampling and clearer activity history

- The desktop monitor now samples every **0.5 seconds** by default. Preferences
  and `--interval` accept **0.25–30 seconds**. One background collector remains
  active at a time, with no queued sampling backlog.
- The activity chart uses actual elapsed time, labelled rate/time axes,
  vertical headroom, a shaded trace and a visible latest-sample marker. Early
  observations use the available plot width while the history fills.
- The canvas adapts between 160 and 240 pixels high to suit its width. The
  caption reports the observed sample count and recorded duration.
- Paused or failed sampling creates a gap when fresh observations resume.
  Stale statistics and history remain visible, with their existing age/status
  indication; no artificial intermediate traffic samples are generated.

```sh
dnsp-gui --interval 0.25 --history 120
```

Rates are averages over their actual sampling intervals, not instantaneous
packet peaks. The history remains bounded by the selected 20–300 sample limit.

### Balanced desktop sections

Connection controls, activity history and information sections use matching
panel borders, padding and gutters. DNS traffic and upstream statistics align
in one row, with cache/filtering and daemon load aligned below. Metric cards
keep equal widths and tabular numeric labels. The chart follows the GTK theme's
foreground color.

Native GTK regressions exercise 1120×920 and 800×680 layouts, quarter-second
sampling, panel geometry, chart gaps and retained data on Ubuntu x86-64 and
ARM64. The README and desktop guide include a current screenshot from the real
local 25-query DNS regression, including five NXDOMAIN replies.

### Build and validation efficiency

- Reuse the verified x64 Python test runtime on Windows ARM64 runners and
  prepared MSYS2 environments keyed by runner image, architecture and workflow
  configuration. Toolchains refresh in seven-day buckets, with validation and
  clean-install fallback when a restored environment is unusable.
- Run independent portable suites with two workers and disjoint listener-port
  ranges. Port-53 launchers, DNS rollback and SCM acceptance remain sequential.
  Per-suite logs/timings, failure propagation and timeout process-tree cleanup
  remain part of validation.
- Cache versioned Python fixture downloads and Linux HTTP/3 benchmark
  dependency layers, rebuilding the test stage from current source.
- Cancel superseded PR validation runs while preserving release publication
  concurrency.

In the measured warm-cache Windows jobs, AMD64 took 229 seconds versus the
355-second release baseline; ARM64 took 379 seconds versus 629 seconds.
These are CI job measurements: hosted-runner timings vary, and initial cache
fills include installation and save overhead. See the
[validation run](https://github.com/fantuz/DNSProxy/actions/runs/44014616755)
and the [cache policy](https://github.com/fantuz/DNSProxy/blob/v4.9.0-modern/docs/CI-PERFORMANCE.md).

### Packages and upgrade

The release includes eight Linux daemon packages, four optional Linux desktop
packages, Windows AMD64/ARM64 ZIPs, macOS Intel/ARM64 archives and `SHA256SUMS`.
Install the updated optional GUI package to obtain the new chart and layout.

The exact tested Debian 13 slim OCI image is published for Linux AMD64/ARM64:

```sh
docker pull ghcr.io/fantuz/dnsproxy:4.9.0
```
