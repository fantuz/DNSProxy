## DNSProxy Modern 4.6.0

This release adds packaged Linux desktop monitoring, bounded latency telemetry
and optional delayed parallel upstream requests to the shared C resolver.

### Desktop monitoring

- The Linux GTK 4 monitor ships as an optional `dnsp-modern-gui` package with a
  desktop launcher and icon. Choose the DEB for Ubuntu 22.04/24.04 or Debian 13,
  or the RPM for Rocky Linux 9. GUI packages are architecture independent and
  tested on both x86-64 and ARM64. GTK dependencies belong to the GUI package.
- Select a running resolver, inspect systemd service state and daemon/libcurl
  capabilities, and view startup options, traffic, cache/filtering statistics,
  CPU and memory. The monitor runs as an ordinary user and reads existing
  metrics; closing it leaves the resolver running.
- Estimated recent p50/p95/p99 latency comes from fixed histogram buckets.
  History is bounded and no queried names or client addresses are collected.

### Optional parallel upstream requests

With a backup configured, `--upstream-hedge-ms 150` can start an eligible backup
after 150 ms while the primary remains pending. The first validated DNS reply
wins and the losing attempt is cancelled. Both attempts share the original
deadline, enforced by the event loop. Primary TLS verification and the existing
cache, EDNS and blocklist policies remain in effect.

The default is `0`, preserving sequential failover. Parallel requests increase
traffic and disclose additional queries to the backup; select resolvers with
equivalent DNS views and policies. At most 16 extra backups can run within the
existing 128-transfer ceiling. See the
[upstream guide](https://github.com/fantuz/DNSProxy/blob/v4.6.0-modern/docs/UPSTREAM_FAILOVER.md).

### Compatibility and release reliability

- Tests adapt to hosts without usable IPv6 loopback; GitHub CI still requires
  IPv6 coverage, and an explicitly requested unavailable listener fails clearly.
- HTTP/2 and HTTP/3 tests cover delayed backups, cancellation and subsequent
  multiplexed work. Sanitizers, parser fuzzing and baseline performance gates
  supplement native Linux, Windows AMD64/ARM64 and macOS Intel/ARM64 tests.
- Release changelogs explicitly start at the previous published release,
  including when earlier manual releases used commits outside master history.
- Downloads contain eight Linux daemon packages, four optional Linux GUI
  packages, two Windows ZIPs and two macOS archives, plus `SHA256SUMS`.

### Upgrade and platform notes

Install the daemon package matching your distribution and architecture. The
GUI package is optional; launch it with `dnsp-gui`. Packaged Linux services
expose metrics on `127.0.0.1:9153`; manual invocations enable them with `-m PORT`.
Parallel requests remain opt-in after upgrading.

Windows includes native console launchers, UAC elevation and service/DNS
configuration tools. A Windows graphical monitor is a future addition. The
portable ZIP names retain their historical `-poc` suffix for download
compatibility. Windows binaries remain unsigned; macOS signing/notarization
also remains a follow-up.
