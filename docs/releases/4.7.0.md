## DNSProxy Modern 4.7.0

This release introduces a Debian 13 slim OCI image for Linux AMD64 and ARM64,
built from the same C resolver as the native packages.

### Container distribution

- Release images are published to `ghcr.io/fantuz/dnsproxy`. One multi-platform
  image reference selects the native AMD64 or ARM64 image automatically.
- The runtime uses Debian libcurl and CA certificates, runs as UID/GID
  `10001:10001`, and supports HTTP/2 with optional HTTP/3. Compilers, Python,
  GTK and systemd are kept outside the runtime image.
- The Compose example publishes both UDP and TCP DNS on host loopback, drops
  all capabilities, enables `no-new-privileges` and uses a read-only filesystem.
  Host port 53 maps to unprivileged port 5300 inside the container.
- The default command supplies an upstream bootstrap address and enables a
  bounded 256-entry in-memory cache. Blocklists and private CA bundles can be
  mounted read-only; directory mounts support atomic blocklist replacements.
- A small loopback health check tests daemon responsiveness without querying
  public DNS. Logs go to stderr. SIGTERM stops the daemon cleanly.

After the initial package publication, the repository owner must set its
[GHCR visibility to Public](https://github.com/users/fantuz/packages/container/dnsproxy/settings)
to enable anonymous pulls. Then try the pinned release with Docker:

```sh
docker run -d --name dnsproxy --read-only --cap-drop=ALL \
  --security-opt=no-new-privileges \
  -p 127.0.0.1:5300:5300/udp -p 127.0.0.1:5300:5300/tcp \
  ghcr.io/fantuz/dnsproxy:4.7.0
dig @127.0.0.1 -p 5300 example.com A
dig +tcp @127.0.0.1 -p 5300 example.com AAAA
docker logs dnsproxy
docker stop --time 10 dnsproxy
docker rm dnsproxy
```

Podman can use the same image and command options. For host port 53, Compose,
HTTP/3, backup upstreams, blocklists and the host desktop monitor, see the
[container guide](https://github.com/fantuz/DNSProxy/blob/v4.7.0-modern/docs/CONTAINERS.md).
Metrics remain private to loopback; publishing port 9153 in bridge mode does
not expose them. The guide documents optional host networking for local
monitoring.

### Build, test and publication integrity

GitHub builds both architectures on native Linux runners and exercises the
actual runtime images for UDP/TCP forwarding, A/AAAA/TXT/unknown record types,
EDNS truncation, cache hits, blocklist reloads, non-root/read-only operation,
health, shutdown and real HTTP/2/HTTP/3 multiplexing and connection reuse.

The tested OCI archives are combined without rebuilding or rewriting their
image manifests, configurations or layers. Source revision, version, platform
and digest checks protect the handoff between build and publication. A local
registry verifies unprivileged upload and idempotent retries; the combined
archive includes explicit directories for rootless Skopeo compatibility.

Container checks join the required PR check and the release gate. Following
successful native package publication, a separate job publishes the exact
tested index to GHCR and checks its digest. The publisher refuses to overwrite
version tags, and `4.7`, `4` and `latest` aliases only advance. PR/snapshot
builds provide OCI artifacts without publishing registry tags.

Windows launcher acceptance also isolates Windows PowerShell's module path
from the CI parent's PowerShell 7 environment and allows a cold PowerShell
host more startup time on ARM64. Startup failures now report the process exit
state and captured output. DNS response deadlines, dual-stack checks and
console shutdown assertions are unchanged.

The listener-failure logging fixture now selects a port checked for both UDP
and TCP outside the usual ephemeral range. This prevents Windows UDP port
exclusions from obscuring the deliberately created TCP listener conflict.

### Native packages and upgrade notes

The release also supplies eight Linux daemon packages, four optional Linux
desktop packages, two Windows portable ZIPs and two macOS archives, with
`SHA256SUMS`. Existing native installation and service configuration remain
available; container deployment is optional.

The Windows ZIP filenames retain their historical `-poc` suffix for download
compatibility. Windows signing and macOS signing/notarization remain follow-ups.
Container SBOMs, signatures and provenance attestations are not included in
this release.
