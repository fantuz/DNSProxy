## DNSProxy Modern 4.12.0

The macOS archives now include a Finder app for the desktop monitor. This
release also adds reproducible comparisons of local resolvers and verifies
published package checksums before promoting the container image.

### macOS downloads and first launch

Choose the Intel or Apple Silicon archive from the download table and verify it
against `SHA256SUMS`. The console launcher, `Start-DNSProxy.command`, uses the
system libraries. To use the desktop monitor, install `gtk4` and `pygobject3`
with Homebrew, move `DNSProxy.app` to Applications and open it. The app includes
its own resolver.

The native executables and Finder app have ad-hoc integrity signatures. Apple
has not notarized these downloads. Open the verified item once. If macOS cannot
verify the developer and you trust the download, dismiss the alert, choose
**System Settings → Privacy & Security → Open Anyway** and confirm
**Open** for that item. Managed Macs may require administrator approval.
[Apple’s Open Anyway steps](https://support.apple.com/en-us/102445#openanyway) ·
[Full Apple guide](https://support.apple.com/en-us/102445) ·
[DNSProxy download and setup](https://github.com/fantuz/DNSProxy/blob/v4.12.0-modern/docs/MACOS.md#download-and-start)

### Resolver performance

The published comparison measured the 4.11.1 resolver with 1, 8 and 32
concurrent UDP clients. On the recorded Ubuntu host, DNSProxy served 107,748
warm queries/s at 32 clients with a p99 of 0.34 ms. Ubuntu’s `systemd-resolved`
stub served 31,296 warm queries/s. On misses, DNSProxy completed 2,681 queries/s
over HTTP/2 and the system stub completed 10,439 over plain UDP. All 4,357,212
measured warm replies across the four caching forwarders used zero upstream
requests. The report includes the AdGuard, dnscrypt-proxy and direct UDP
results, latency percentiles, resource usage and commands to repeat the tests.
Two candidate optimizations remain documented experiments.
[Benchmark report and raw data](https://github.com/fantuz/DNSProxy/blob/v4.12.0-modern/docs/benchmarks/linux-doh-2026-11-27/README.md)

### Distribution and maintenance

Release publishing checks GitHub’s SHA-256 digest for each package and the
checksum manifest. A fresh release must match the tested build before the OCI
image is promoted. External Actions use full commit SHAs, with weekly Dependabot
checks for Actions and the Python protocol fixtures. Ubuntu CI installs build
dependencies from the runner’s signed distribution archives. The repository adds a bug
report form, pull request template, contribution guide and code of conduct.
