## DNSProxy Modern 4.11.0

This release adds client DNS response codes to Prometheus and the desktop,
extends the optional answer cache, and lets administrators change Windows
service settings in place. It includes the changes from [#86](https://github.com/fantuz/DNSProxy/pull/86)
and [#87](https://github.com/fantuz/DNSProxy/pull/87).

### Resolver caching

The in-memory cache now accepts positive IN SVCB and HTTPS answers alongside
A and AAAA. All four query types also support direct NXDOMAIN and NODATA
caching when the response contains one SOA for the queried name or an enclosing
zone. The negative lifetime uses the lower of the SOA TTL and MINIMUM. HTTP
freshness, the upstream HTTP `Age` and the local retention limit also apply.

Reuse requires an identical wire query apart from its transaction ID, including
the query type. With caching enabled, five consecutive requests for each of
four loopback test cases (HTTPS, SVCB, NXDOMAIN and NODATA) produced one
upstream request per case. The daemon defaults to zero cache entries.
Set `--cache-entries N` to a value from 1 to 1024 to enable it.

### Desktop settings and monitoring

- The resolver editor now covers multiple listeners, filtering files and
  reload policy, connection limits, TCP and DoH deadlines, and the UDP reply
  ceiling. Changing a provider hostname clears its inherited bootstrap IP.
  Applying a filtering configuration runs the selected resolver's blocklist
  check and displays any diagnostic before saving.
- Prometheus exposes `dnsp_client_responses_total` by DNS response code. It
  counts replies after a successful UDP send or complete TCP write, including
  cache hits and local policy replies. A provider replying HTTP 200 with a
  valid DNS SERVFAIL increments both the upstream success count and the client
  SERVFAIL count once the reply is delivered.
- The desktop shows recent DNS outcomes, upstream failures, cache hits and
  connection reuse. The Monitoring tab adds primary and backup outcomes,
  HTTP versions, mean queue/TLS/first-byte times, live capacity and sample
  age. Diagnostics can export these aggregate readings to JSON. Older
  resolvers show unavailable readings for metrics they do not expose.

### Windows service configuration

Open **Modify DNSProxy service** from the Start menu to change listeners, ports,
the HTTPS upstream and bootstrap IP, or startup mode. The tool checks changed
ports before stopping the service and verifies DNS over UDP and TCP on each
configured listener. A failed health check restores the previous configuration.
A previously stopped service returns to its stopped state after verification.

The installer and portable distributions also include
`Set-DNSProxyService.ps1` for partial updates and recovery after an interrupted
change. For example, enable metrics on an installer-managed service from an
administrator PowerShell window with the following command.

```powershell
& "$env:ProgramFiles\DNSProxy\bin\Set-DNSProxyService.ps1" -MetricsPort 9090
```

### Native macOS build

The native build compiles independent targets two at a time and strips unused
code at link time. It retains portable `-O2` settings and verifies the
architecture and macOS 15 deployment target of both packaged executables.
On a virtual Apple M1, four warm builds per profile gave median compile-and-package
times of **2.60 s** for the sequential profile and **2.43 s** for the release
profile, a **6.5%** reduction in that run. [Apple Silicon benchmark](https://github.com/fantuz/DNSProxy/actions/runs/44641803300/job/135974650484)
