## DNSProxy Modern 4.8.0

This release keeps the Linux desktop monitor steady during slow or failed
metrics reads, adds traffic and latency insights, and introduces monitor
preferences plus an ordinary-user resolver launcher.

### A stable display during delayed updates

- The GUI retains the last valid numbers, startup settings and activity chart
  when a scrape fails. **No fresh data** and the sample age distinguish retained
  statistics from current measurements.
- Successful snapshots update changed values together, without clearing the
  display first. Worker results reach GTK directly; one collector runs at a
  time with no queued sampling backlog.
- Recovery starts a new rate baseline, avoiding a false QPS spike. Selecting
  another instance, observing a process restart or detecting a counter reset
  clears the previous instance's values and peaks.
- CPU, memory, uptime, startup settings and service status remain available
  when traffic metrics are disabled.

### Additional statistics and clearer presentation

The overview adds peak sampled QPS, CPU, resident memory and inflight work,
cache-hit and failed-attempt ratios, and reused attempts as a percentage of
completed attempts. Card typography, numeric alignment and spacing are improved.

The daemon now exports exact lifetime maximum durations for completed upstream
attempts and fully written UDP/TCP client replies. Upstream maxima include
completed failures and exclude cancelled losing parallel attempts. Older daemons
without these gauges show dashes. Sampled QPS and resource peaks describe this
GUI session; QPS is an interval average, not an instantaneous packet peak.

### Preferences and resolver configuration

Preferences applies the refresh interval, metrics socket timeout, bounded chart
history, automatic sampling and chart visibility immediately. CLI equivalents
initialize the same controls:

```sh
dnsp-gui --interval 0.5 --timeout 2 --history 120
dnsp-gui --paused
```

The separate **Launch resolver** form previews a validated CLI invocation and
starts a new resolver as the desktop user. Checkboxes enable metrics, caching,
EDNS padding, HTTP/3 preference, backup upstreams, delayed parallel requests and
blocklists. Fields select addresses, ports, upstream URLs, bootstrap addresses,
cache size, delay and optional blocklist/CA files.

Launching uses an argument list without a shell. The form accepts ports
1024–65535. Stop targets only the child started by that window; closing the GUI
leaves it running. Existing services and system DNS retain their usual
configuration procedures. Demo mode permits preview and disables launching.

### Regression coverage

New tests cover real HTTP timeouts and recovery, retained numeric labels,
process-only monitoring, exact latency maxima and launcher isolation. A small
original query list uses the DNS-OARC/dnsperf `NAME TYPE` format: one paced pass
of 25 queries, with five NXDOMAINs among 20 successful A/AAAA/TXT/MX/NS/SOA
replies. Tests observe the real GTK labels and verify that NXDOMAIN counts as a
satisfied DNS reply without increasing upstream failures. A separate 48-query
NXDOMAIN burst remains covered. Controlled local replies keep CI repeatable.

### Packages and upgrade

Upgrade both the daemon and optional GUI to obtain the new lifetime maximum
gauges. The release supplies eight Linux daemon packages, four Linux desktop
packages, Windows AMD64/ARM64 ZIPs, macOS Intel/ARM64 archives and `SHA256SUMS`.

The Debian 13 slim OCI image is also published for Linux AMD64 and ARM64 from
the exact tested image index:

```sh
docker pull ghcr.io/fantuz/dnsproxy:4.8.0
```

GTK remains an optional host-side package. For monitoring a container, use the
host networking procedure in the container guide; metrics remain loopback-only.
