## DNSProxy Modern 4.12.1

The desktop monitor uses less CPU when it displays a resolver it launched.
Windows release builds now refresh and verify the transport libraries shipped
in both installers and the portable ZIP.

### Desktop CPU use

The monitor checks its child resolver every 50 ms. It now formats and redacts
the diagnostic log once per change, then reuses that text on subsequent polls.
The PR benchmark measured median CPU time per snapshot with an unchanged
64 KiB log and the Python runtime bundled for each Windows architecture.

| Windows architecture | Before | After |
| --- | ---: | ---: |
| AMD64 | 3.75 ms | 0.219 µs |
| ARM64 | 7.19 ms | 0.359 µs |

These timings cover the GUI's log snapshot. Separate forwarding tests found
that an experimental TCP loop change reduced warm-cache throughput by 9.5%
on Windows AMD64 with 32 clients. The production resolver retains the 4.12.0
forwarding loop.

[Resolver measurements](https://github.com/fantuz/DNSProxy/blob/v4.12.1-modern/docs/benchmarks/tcp-slots-2026-11-28/summary.md)

### Updating libcurl on Windows

Upgrade with the installer for your architecture, or extract the complete new
portable ZIP into a fresh directory. Run `dnsp-modern.exe --version` to see
the libcurl version loaded at runtime. The ZIP's `BUILD-INFO.txt` lists the
exact MSYS2 package revisions.

Release builds refresh the native MSYS2 packages and test the executable
from the extracted ZIP. Weekly AMD64 and ARM64 builds compare curl, OpenSSL,
nghttp2, nghttp3 and ngtcp2 against the published package inventory.
[Windows update guide](https://github.com/fantuz/DNSProxy/blob/v4.12.1-modern/docs/WINDOWS.md#libcurl-and-bundled-dll-updates)

### Tests and maintenance

A new regression test covers TCP client slots being reused as connections
close and reopen. The HTTP/3 test fixture uses aioquic 1.9.2. CI also updates
the pinned checkout, Python setup and cache actions. The installer license
screen now displays the updated project copyright notice and the maintainer's
HB9GUS callsign.
