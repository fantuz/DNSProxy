## DNSProxy Modern 4.10.0

This release adds standard Windows setup installers and extends the shared
desktop interface to Windows and macOS. The native C resolver remains
independent of the optional Python/GTK interface.

### Windows installation and service options

AMD64 and ARM64 setup EXEs install the resolver, native dependencies, service
utilities and Start Menu shortcuts into protected Program Files. Service
registration is optional and initially unchecked. The wizard configures the
DNS port, HTTPS upstream and numeric bootstrap address, IPv6 loopback,
automatic startup, immediate start and a separate loopback metrics port.

The service runs as `NT AUTHORITY\LocalService`, using the native Windows SCM
adapter, restricted permissions, crash recovery and rotating logs. Installing
the application or service does not change adapter DNS settings or add a
firewall exception. Adapter DNS integration remains an explicit operation
through the reversible DNS helper.

Upgrades of setup-managed installations preserve the exact service command,
startup mode, protected state, logs and previous running/stopped state. Adding
the desktop component does not enable metrics on an existing service. Restore
any managed adapter DNS configuration before upgrade or removal; an active DNS
recovery record blocks those operations. Portable service installations retain
their separate installation and removal procedure.

For a new portable service installation, run the following from an
Administrator PowerShell in the extracted ZIP:

```powershell
.\Install-DNSProxyService.ps1 -MetricsPort 9090
Get-Service DNSProxy
```

Metrics are disabled by default in the portable service script and smaller
resolver/service setup. The desktop setup defaults a new service's metrics
port to 9090. A value of 0 disables metrics; the metrics and DNS ports must
differ. The listener accepts read-only requests on `127.0.0.1`.

### Shared desktop interface

- Query activity selects all queries, UDP or TCP; latency history selects
  estimated client-reply p95 or completed upstream-attempt p95. The plots sit
  side by side on wide windows and stack on compact windows, with consistent
  panel spacing and alignment.
- Sampling retains its 0.5-second default and 0.25–30-second range. One background
  collector runs at a time. Histories and diagnostics are bounded; failed or
  paused samples create gaps, while stale displays retain their last valid
  values and freshness indication.
- Grouped resolver options include file pickers, validation and a redacted
  command preview. The Diagnostics tab displays recent output and startup/exit
  errors from the resolver launched by that window.
- Native Windows and macOS adapters read process identity, executable paths,
  available arguments, CPU, resident memory and service state. Permission
  restrictions are reported as unavailable. Explicit metrics-port connections
  support traffic-only monitoring when process details cannot be inspected.

On Linux, the installed desktop command can monitor an existing resolver with
metrics enabled:

```sh
dnsp-gui --metrics-port 9090 --interval 0.5 --history 120
```

Connect/Disconnect observes an existing endpoint without controlling its
process. Start/Stop and window close affect only the resolver owned by that
GUI window. Closing stops and reaps that child, with bounded forced termination
if graceful shutdown fails; unrelated resolvers and services remain running.
The GUI runs as an ordinary user and does not configure services or adapter DNS.

### Windows and macOS desktop delivery

Windows AMD64 and native ARM64 desktop installers bundle private Python/GTK
runtimes and add a **DNSProxy desktop** shortcut. No separate Python or MSYS2
installation is required. Each architecture has a matching GUI-runtime source
ZIP containing corresponding sources, recipes, licenses and package/version
records. The private runtime is not required by the Windows service.

macOS Intel and Apple Silicon archives include shared GUI source and
`Start-DNSProxy-GUI.command`. Install the optional Homebrew dependencies, then
run the launcher from the extracted archive:

```sh
brew install gtk4 pygobject3
./Start-DNSProxy-GUI.command --metrics-port 9090
```

The launcher selects a compatible Homebrew Python without replacing system
Python or changing global PATH. The native CLI and launchd service do not
require Homebrew. For a new monitored launchd installation, use
`sudo ./dnsp-macos install --metrics-port 9090`; omission or a value of 0 keeps
metrics disabled. Existing installations require explicit reconfiguration.

Windows setup EXEs and native binaries are unsigned. macOS binaries are not
Developer ID signed or notarized; the GUI is a Homebrew launcher rather than
a self-contained `.app`. CPU time and process uptime are unavailable with
Rosetta-translated Python on Apple Silicon; a native interpreter is preferred.

### Packages and validation

The release supplies **22 assets plus `SHA256SUMS`**:

| Distribution | Assets |
| --- | ---: |
| Linux daemon packages | 8 |
| Optional Linux GUI packages | 4 |
| Windows AMD64/ARM64 portable ZIPs | 2 |
| Windows resolver/service setup EXEs | 2 |
| Windows bundled GUI setup EXEs | 2 |
| Matching Windows GUI-runtime source ZIPs | 2 |
| macOS Intel/Apple Silicon archives | 2 |

Native desktop tests open GTK windows, exercise wide and compact layouts,
settings, diagnostics, local UDP/TCP traffic, metrics and latency updates, and
owned-process shutdown while an external resolver remains running. Windows
acceptance also exercises installed shortcuts, private-runtime isolation,
install/upgrade/uninstall and retained user data. Mac tests use source and
launchers extracted from the same archive as the tested resolver. Screenshots
and structured results are retained as CI artifacts. Publication requires both
Windows desktop installer jobs and the existing native, Linux packaging and
sanitizer gates; published packages are the tested artifacts.

The Debian 13 slim OCI image is published for Linux AMD64 and ARM64 from the
tested image index:

```sh
docker pull ghcr.io/fantuz/dnsproxy:4.10.0
```
